## Integrando DynamoDB

- DynamoDB é um serviço de banco de dados. Ele também é serverless e escala automaticamente.
- Paga-se por leitura e escrita (pay-per-request)
- É um esquema chave-valor
- A latência é de milissegundos
- É redundante (multi AZ)

### Quando usar
- Precisa de latência baixíssima
- Acesso com padrão previsível
- Os dados têm uma chave natural muito identificável

### O modelo DynamoDB
- É um modelo que utiliza NoSQL, que é diferente dos bancos relacionais comuns.
- É importante saber o padrão de acesso antes de fazer o esquema.

    #### Como é composto um banco DynamoDB
        - Tabelas: Equivalente a tabelas SQL
        - Itens: similares a uma linha de uma tabela
        - Atributos: similares a colunas de uma tabela
        -  Flexibilidade de schema: itens podem ter diferentes atributos sem modificar o banco todo
        - Atributos podem conter tipos de dados complexos, como listas e mapas. 

    #### Primary keys e partition keys
        - Partition keys (hash key) são necessárias para todos os itens. É a partir delas que eles serão localizados. Partition keys identificam em qual nodo o item está.
        - Sort key: chave de ordenação. É a segunda parte opcional de uma partition key. Serve também como identificador, como uma chave primária composta, quando aparece junto de partition keys.
        - Unique identification: necessário para identificar os itens
        - Secondary indexes: ajudam a adicionar outros padrões de acesso, pois pode ser que a necessidade de fazer o sort da tabela mude. Local Secondary Indexes (LSI) usam a mesma partition key com sort key diferente  e Global Secondary Indexes (GSI) usam partition e sort keys completamente diferentes. Secondary indexes são como uma tabela duplicada com partition keys diferentes
    
    #### Tipo de dados
        - String
        - Number (inclui decimais)
        - Lista
        - Mapa (são dicionários em JSON)
        - Booleano
        - Outros: binário, string set, number set, binary set e nulos.
