# Building your first serverless API

## Objetivos do módulo
- Construir REST APIs usando Lambda e AWS API Gateway
- Identificar estágios do ciclo de vida do runtime da Lambda
- Aplicar princípios de design REST, incluindo métodos HTTP, códigos de status e URL baseadas em recurso
- Fazer o deploy de uma API serverless usando AWS CDK e testar endpoints com comandos curl

## Função Lambda

- Toda função Lambda tem um handler com um event (com o que acionou ela) e um context (quanto tempo de execução restante)
- Event é sempre um dicionário JSON
- Return é o que a Lambda devolve
- Toda Lambda é acionada por um gatilho (por exemplo, uma API Gateway recebe uma requisição, que converte a requisição HTTP em um JSON que vai para o handler).
- Nesse caso, o API Gateway pega a resposta da Lambda e leva de volta ao cliente
- É boa prática envelopar o código em blocos try/except para error handling
- Runtime é o ambiente de execução (Python 3.12, Node 20, etc)
- Warm start: inicialização do ambiente compartilhado fora do handler
- Cold start: a primeira execução de uma Lambda depois de um tempo parada é um pouco mais lenta, pois a AWS precisa "acordar" o ambiente.
- Layers são bibliotecas reutilizadas

## Criando a Lambda

- Author froms scratch permite criar uma lambda do zero, sem um padrão (blueprint) ou um container
- Nome da função: tem que ser único na região. Pra renomear uma Lambda, é necessário recriá-la.
- Escolha de runtime: é a escolha da linguagem, basicamente
-  ARM64 é o padrão da AWS, pois é o mais comum
- Custom execution role é o role IAM da Lambda, que precisa ser configurado para que ele tenha permisão de fazer coisas com os serviços AWS. Se deixado vazio, ele só registra logs
- ARN é o endereço da Lambda
- A Lambda cria um arquivo inicial padrão
- O padrão de toda Lambda é: chama o evento, pega os dados necessários com .get() e retorna o necessário (padrão caller, event, handler, response)
- O nome da Lambda é lambda_function(nome do arquivo).lambda_handler. Se o nome do arquivo mudar, precisa mudar o nome do handler para ficar igual
- Mais memória = função rodando mais rápido
- Timeout padrão é 3s. Pode mudar até 15s.


## API Gateway

- API Gateway é quem faz o intermédio da chamada HTTP na aplicação e muitas vezes invoca a Lambda.
- Processo do API:
    1. Autenticação: valida chaves de API, IAM roles e autorizações customizadas
    2. Valida a chamada: checa os parâmetros requeridos e o formato da requisição
    3. Limite de taxas: aplica regras de throttling para gerenciar volume de chamadas
    4. Transformação da requisição: mapeia a requisição HTTP para o formato de evento Lambda
    5. Invocação da Lambda
- Existem duas formas de conexão com a Lambda:
    - Proxy integration: é recomendada e é mais comum, passa todos os detalhes de requisição para a Lambda. Você tem controle total dos dados da requisição. A resposta da Lambda também é a requisição inteira.
    - Non-proxy integration: edita o mapeamento da requisição HTTP e você só recebe uma parte dos detalhes. É útil para 
- A Lambda proxy retorna: status code, header, body (em formato de dicionário JSON)
- Se faltar qualquer coisa na resposta da Lambda de volta pro API Gateway, ela dá erro
